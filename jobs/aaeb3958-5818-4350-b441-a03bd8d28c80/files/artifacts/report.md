## 4. Hook spec: callbacks and permission flags, hookData schema, fee math with one worked example, invariants, admin surface

**Record — verified live scope.** Ethereum CLAUS token is `0x1b54E762aa34CF6E28E9C082F2848e28E45DA6b8`; hook is `0x37Bfb8AC7C960E558657871D41Ca70E07e7DbfFf`; extension host is `0xea0436465676eA7001535Bfe2E5cbd4b137b7f91`. The hook proxy resolves to `0xa62f9b597225779b430024398B70374E8468Ce14`. Sourcify's matched source runtimes were compared byte-for-byte with pinned chain code for the proxy, implementation, host, token implementation, governance, active adapter and compute collector. This is source verification and read-only inspection, not an audit. [Hook proxy](https://sourcify.dev/server/v2/contract/1/0x37Bfb8AC7C960E558657871D41Ca70E07e7DbfFf?fields=all), [ProtectedHook](https://sourcify.dev/server/v2/contract/1/0xa62f9b597225779b430024398B70374E8468Ce14?fields=all), [host](https://sourcify.dev/server/v2/contract/1/0xea0436465676eA7001535Bfe2E5cbd4b137b7f91?fields=all).

**Record — every live callback and flag.** The address's low permission bits are `0x3fff = (1 << 14) - 1`, so all callback and return-delta flags are enabled. This must not be confused with the much smaller set a new implementation would need. [Pinned Uniswap flag definitions](https://github.com/Uniswap/v4-core/blob/bea7f6d1c11cd5dc4f0d5151ffa37a1c239feee6/src/libraries/Hooks.sol), [interface](https://github.com/Uniswap/v4-core/blob/bea7f6d1c11cd5dc4f0d5151ffa37a1c239feee6/src/interfaces/IHooks.sol).

| Live v4 callback | Permission bit, Record | Purpose in inspected source, Record |
|---|---:|---|
| `beforeInitialize` | `1 << 13` | Validate the original initializer, token, opening price and canonical pool parameters; one initialization |
| `afterInitialize` | `1 << 12` | Set dynamic LP fee to zero |
| `beforeAddLiquidity` | `1 << 11` | Inherited manager-checked acknowledgement |
| `afterAddLiquidity` | `1 << 10` | Inherited acknowledgement, zero hook liquidity delta |
| `beforeRemoveLiquidity` | `1 << 9` | Inherited manager-checked acknowledgement |
| `afterRemoveLiquidity` | `1 << 8` | Inherited acknowledgement, zero hook liquidity delta |
| `beforeSwap` | `1 << 7` | Quote module; pin transient fee plan; calculate specified-side hook delta |
| `afterSwap` | `1 << 6` | Account fees and ceiling; inherited processing; record trade for original module; clear transient plan |
| `beforeDonate` | `1 << 5` | Inherited manager-checked acknowledgement |
| `afterDonate` | `1 << 4` | Inherited manager-checked acknowledgement |
| Return-delta flags, not extra callbacks | `1 << 3`, `1 << 2`, `1 << 1`, `1 << 0` | Respectively before-swap, after-swap, after-add-liquidity, after-remove-liquidity return deltas |

**Record — hook rules versus job rules.** `TradeExtensionHost.quote` static-calls the selected module with bounded gas and validates six allocations whose sum cannot exceed `149,000` pips. The permanent core checks the aggregate tax ceiling of `150,000` pips. `record` authenticates the hook. `execute` later consumes an original receipt outside an unlocked PoolManager and calls the original module; failure reverts that delivery, not the completed swap. `onTrade` is a module callback; `unlockCallback` is a PoolManager unlock callback. Neither is an additional v4 hook-permission callback. There is no live “independent seat reran this work” gate in the permanent hook.

**Record — sender and hookData.** PoolManager forwards its caller as `sender`: ordinarily a router, not the end trader. The host passes this sender and arbitrary `bytes hookData` to `quote`, and commits `keccak256(hookData)` in its receipt. It rejects data longer than `4,096` bytes. Empty data works. A bare address in hookData and `tx.origin` are not authenticated trader identities. [Uniswap's caller forwarding](https://github.com/Uniswap/v4-core/blob/bea7f6d1c11cd5dc4f0d5151ffa37a1c239feee6/src/libraries/Hooks.sol), [verified host](https://sourcify.dev/server/v2/contract/1/0xea0436465676eA7001535Bfe2E5cbd4b137b7f91?fields=all).

**Inference — smallest experimental schema:** swap `hookData = bytes("")`; all fees are uniform; nobody is metered as a trader. Job submissions use a separate typed message containing `jobId, chainId, consumer, specHash, stateBlockHash, artifactHash, callsHash, operator, payout, nonce, deadline`. This avoids introducing trader signatures, router allowlists or a venue lock. Any future trader discount would require an EIP-712 authorization binding the trader, authorized router, PoolId, direction, amount bounds, nonce and deadline, plus router-side verification that its authenticated payer is that trader. That integration is outside the experiment.

**Record — current fee economics.** The [fee-state snapshot](https://claus.si/fee-state.json) reports a total of `23,000` pips of gross ETH, or `23,000 / 1,000,000 = 2.3%`, with wallet `12,000`, compute `1,000`, burn `1,500`, reserve `2,000`, NFT `3,500`, platform `3,000`; their sum is `23,000`. LP rewards are paused and their current allocation is zero. The reserve is not a current payment to LP stakers. The active module is an adapter, not the compute collector directly. [Verified adapter](https://sourcify.dev/server/v2/contract/1/0xde812d12c3f02b9582c4775585de928fa7142d71?fields=all).

**Inference — worked example using the recorded plan, not observed volume:** for a gross exact-input buy of `1 ETH`, total hook charge is `1 × 23,000 / 1,000,000 = 0.023 ETH`, leaving `0.977 ETH` for the pool-side swap before price impact. Allocations are wallet `0.012`, compute `0.001`, burn `0.0015`, reserve `0.002`, NFT `0.0035`, platform `0.003 ETH`; sum `0.023 ETH`. This assumes no additional protocol fee and is not an all-in quote. Exact-output buys require gross-up, approximately `net / (1 - 0.023)`; actual integer rounding follows the pinned `FeeMath`. No additional crew surcharge is proposed. A funded crew would need an authorized reassignment of existing proceeds, not another fee on top.

**Inference — required experimental invariants:** ordinary transfers remain exact; no mint or blacklist; other venues remain usable; swaps never wait for a model, reviewer or oracle; jobs spend only prefunded escrow; no duplicate job/receipt payment; payout recipients are bound before execution; a failing postcondition reverts target calls and reward credit atomically; royalty/LP liabilities cannot fund jobs; expired jobs refund only unearned escrow. Fee collection is not proof that useful work occurred.

**Record — admin surface, decisive failure.** The core freeze is real: the hook admin's ownership was renounced at Ethereum block `26,197,788`, `2026-10-15T12:03:11Z`, transaction [renunciation](https://etherscan.io/tx/0x9e1edba406365bf9ad470ce7868920b5cb69966ca7bdacaa6778ad58ee2c20a8). Current admin `owner()` returns the protocol's null-owner value. This is observed state, not a placeholder address. However, token `owner()` now returns governance `0x180eae784dee739fbab432b06f78bf9a98aae334`. Its verified code allows the operator to switch approved adapters immediately, the founder to change operator immediately, and the founder to start return of token control. No time delay is enforced in these paths. A two-step ownership transfer is not a timelock. [Governance](https://sourcify.dev/server/v2/contract/1/0x180eae784dee739fbab432b06f78bf9a98aae334?fields=all), [protected token implementation](https://sourcify.dev/server/v2/contract/1/0x55D555bd85feD6ecf30fdA9B4c76019B844218A7?fields=all).

**Inference — a compliant counterfactual, not the live system:** use a new immutable `CrewHook` with `beforeInitialize`, `beforeSwap`, `afterSwap`, before-swap-return-delta and after-swap-return-delta enabled: mask `0x20cc = 8192 + 128 + 64 + 8 + 4`; all other flags false. The hook owns the prefunded job ledger and an external `executeJob` entrypoint verifies signatures/postconditions outside swap callbacks. Only fee rules run inside swaps. Existing CLAUS could trade in this optional new pool without restricting transfers elsewhere; existing fees would not automatically follow it. Use **no admin key** for this new hook; job sponsors only choose terms for their own deposits. Adapting the frozen hook cannot add this entrypoint. If CLAUS instead keeps its existing module lane, every relevant governance/recovery path must migrate behind a verified delay of at least `24 hours = 86,400 seconds`, with no founder bypass. Neither migration nor new pool adoption is approved or proven here.

## 5. Agent spec: signatures, pinned question, verification before pay, payments and failures

**Inference — choose the smallest job honestly.** The smallest objective live chore found is calling `claimActive(amount)` on the compute collector: it burns the collector's already accrued PoolManager claims and pays its immutable beneficiary. The caller cannot choose a recipient. A wrapper can measure the claim balance decrease and recipient ETH increase atomically. That is verifiable today, but a plain keeper can do it. It is therefore a useful baseline and **fails hard requirement 1 as a CREW product**. [Verified collector](https://sourcify.dev/server/v2/contract/1/0xa25ca2d2521aa47b6cc84b28be66e8fc7a1b768e?fields=all).

**Record — census baseline actually checked.** Two `Initialize` log filters, from genesis through Ethereum block `26,257,499`, selecting CLAUS as currency0 or currency1, returned `216 + 35 = 251` distinct PoolIds at canonical PoolManager `0x000000000004444c5dc75cB358380D2e3dE08A90`. Deduplication used transaction hash/log index and separately checked unique PoolIds. Exactly one initialization uses the CLAUS hook. This is a census of initialized v4 pools at that manager, not funded pools, active markets, v2/v3 pools, other managers or other chains. Raw queries/results are in `research/pool-initializations.json`; event semantics are in the [pinned PoolManager interface source](https://github.com/Uniswap/v4-core/blob/bea7f6d1c11cd5dc4f0d5151ffa37a1c239feee6/src/interfaces/IPoolManager.sol). Signing the census adds provenance, not intelligence. A contract cannot infer complete historical enumeration from a signed list alone.

**Inference — only credible AI hypothesis to test:** given a previously unseen, verified CLAUS-related fee-program interface and a pinned state, an agent synthesizes the missing bounded recovery-call sequence from source and ABI, while a precommitted generic keeper fails to produce it. Execute only against sponsor-authorized targets/selectors with an immutable proceeds recipient and a minimum recovered-value condition. Do not give the agent arbitrary treasury authority. If all available cases reduce to known selectors, use the keeper and stop. This is an operational hypothesis about handling new interfaces, not proof that software in principle cannot perform the task. No qualifying instance was demonstrated during this research.

**Inference — identities and signatures:** NFT holders sign a seat-key authorization binding NFT contract/tokenId, ERC-8004 agentId, operator, payout destination, expiry and nonce. Check current ownership when accepting a job; a transfer invalidates unused authorization. Worker's EIP-712 signature binds the exact job/spec, source and execution hashes. A different controller's reviewer signs that same digest after recreating the result; the reviewer cannot be the worker, sponsor or their declared payout beneficiary. Same-controller exclusion is a necessary check, not proof of disinterest. Freeze membership and payout for each accepted job so an NFT transfer cannot steal a pending reward. Existing IMD workers may supply bids through this adapter; automatic IMD admission to another network was not verified.

**Record — oracle functionality verified, trust not erased.** IMD's public API returned one EIP-712 `OracleAttestation` and one signature for request `6faa93d8-edc2-4a44-be4e-fbeafdf43fa8`, attested `2026-10-23T18:58:46.234Z`. Local `cast wallet verify --data --from-file` recovered the advertised attester after normalizing the API's `answerType: "bool"` to its specified enum value `0`. This verifies the signature, not the underlying question's truth or panel independence. The panel members do not each supply a separately contract-checked signature. [Actual attestation](https://api.imd.fun/oracle/requests/6faa93d8-edc2-4a44-be4e-fbeafdf43fa8/attestation), [oracle request interface](https://imd.fun/docs/#the-attestation).

**Inference — exact yes/no question template, frozen before a trial:** “At the pinned Ethereum state block and under the attached immutable job specification, does artifact H provide a reproducible call sequence that increases the specified fixed recipient's ETH balance by at least the specified minimum, preserves every stated liability and authorization invariant, and succeeds on the held-out case on which the precommitted keeper baseline fails?” H, state-block hash, baseline hash, target code hashes and minimum come from the accepted job record; these are unresolved deployment-time inputs, not invented identifiers. The expanded document's canonical hash is pinned before paying for a question. Answer type is **bool only**. There is no numerical oracle question in the proposed experiment.

**Inference — verification and payout sequence:**

- Sponsor prefunds both worker and independent verification budgets before bidding. Bonds are separately accounted CLAUS collateral; no specified bond amount is economically justified yet. For the fork experiment use accounting variables and real historic prices only if available, not a guessed mainnet bond.
- Worker commits its sequence and artifact; reviewer independently reconstructs it in a fresh, network-isolated fork at the same block. Compare outcome and invariants, not identical model wording. Reviewer commits before seeing another reviewer's result.
- The execution wrapper accepts only the exact authorized sequence, snapshots fixed-recipient balance and liabilities, runs bounded calls, and requires the postcondition atomically. Payout credit is created only after success. Calls that cannot be measured atomically are ineligible for the first job class.
- In the optional oracle trial, require the pinned attester and exact domain/consumer, requestId, questionHash, bool encoding, chain/window/blockHash, quorum, issue/expiry times and unused nonce. Require the same artifact and spec hashes in the question. A valid signature for another consumer or question is worthless. Expired/no-quorum/ambiguous results cause no worker payment and eventual refund.
- Credit worker and reviewer to prebound pull-payment balances after acceptance; withdrawal is separate so recipient failure cannot break settlement. No bounty for a failed worker delivery. Verification work may have its own prefunded, verifiably delivered receipt; do not pretend honest reviewers can always be unpaid on rejection. A stolen sequence must not steal the worker's credit.

**Inference — failure modes:** false-positive tests; a malicious sandbox; RPC omission or reorg; shared controllers; reviewers copying work; replay and expired signatures; oracle-signer compromise; ETH balance changes caused by the worker donating its own ETH; flash-funded “recovery”; claim accounting rounded into dust; reverting recipients; jobs manufactured by insiders to farm fees; and CLAUS bond price falling during a dispute. Exclude donation- and wash-generated gains by tracing the authorized claim debit as well as recipient credit. Onchain success does not establish that AI was necessary; compare with the baseline separately. Slash only objectively provable faults such as conflicting signed outcomes for the same immutable job, not model disagreement. No zero knowledge component is proposed: proving execution would still leave oracle truth and controller independence unresolved.

**Inference — seven hard gates, applied without waivers:**

| Requirement | Current decision | Reason / what would change it |
|---|---|---|
| AI does onchain work plain code cannot, paid onchain | **FAIL** | Existing claim/census work is deterministic. Novel-interface synthesis and incremental value are unproven |
| v4 hook enforces rules; callbacks named | **FAIL for live CREW** | Existing hook enforces fee accounting, not job acceptance. A task-module callback alone does not meet the strict hook requirement; counterfactual hook specified above |
| No transfer fees/restrictions/venue locks/postlaunch mint | **PASS for inspected current token surface** | ProtectedToken uses ordinary ERC-20 accounting, burn and metadata; no new token proposed. This is source inspection, not a historical full-system audit |
| No admin or at least a 24-hour timelock | **FAIL** | Frozen core coexists with immediate governance/module changes and founder recovery |
| Fair opening, snipers and bundles addressed | **NOT PROVEN** | No new asset sale in experiment. For any later market opening see below; the historical launch is not retroactively certified |
| Holder/LP rewards without killing volume | **NOT PROVEN** | Burn/NFT allocations exist, LP payout is paused, and no causal volume/fee sensitivity study was established |
| ZK only to remove trust, optional | **PASS** | None used; do not attach a proof to a still-trusted oracle and call the result trustless |

**Inference — fair opening:** the experiment issues no token, NFT or discounted buy allocation, so sniping or bundling buys cannot obtain privileged job rights. Buying more CLAUS is not an admission credential. Collect sealed job bids over a preannounced window and reveal before selection; do not reward first transaction position. Controller screening remains a limit. If an optional new pool is ever opened, publish terms and start block in advance and use a prefunded batch opening at a uniform clearing price rather than privileged first-block purchases; count all bundled orders in that batch, with no per-wallet cap masquerading as Sybil resistance. Existing CLAUS trading elsewhere cannot be stopped, and builders can still trade those venues. No auction implementation or fairness proof was verified here; it is a launch prerequisite, not an achieved feature.

## 6. Economics: day-one payer, unit costs and break even

**Record — money exists, but authority matters.** Collector `0xa25ca2d2521aa47b6cc84b28be66e8fc7a1b768e` had `369,233,351,306,046,421 wei / 10^18 = 0.369233351306046421 ETH` of redeemable claims at our Ethereum pin; its other reported balance was zero. `active()` binds the operator `0xAB716305E5A8854c0DD08397087dbDD56eA32073`. The current fee JSON reports the same amount and `automaticProviderPayments: false`. This is not the crew's treasury and is not evidence of agreed spending. [Verified collector](https://sourcify.dev/server/v2/contract/1/0xa25ca2d2521aa47b6cc84b28be66e8fc7a1b768e?fields=all), [fee snapshot](https://claus.si/fee-state.json).

**Inference — who pays on day one:** only the CLAUS operator, if it explicitly prefunds the experiment from its permitted compute budget or its own funds. Its motive is recovering proceeds or avoiding a demonstrably costly missed operation. Holders and LPs are not presumed customers; a permissionless claim caller does not acquire the right to skim the claim. No customer commitment, escrow deposit for CREW, quote for model/reviewer labor or willingness-to-pay was found. Therefore there is **no verified day-one payer** today. Without that commitment, spend no further IMD and do not launch. IMD is the procurement venue, not an assumed subsidy.

**Record — platform unit costs and cadence.** Capabilities lists jobs, launches and oracle requests at `500000000000000000 / 10^18 = 0.5 IMD` each; scheduled runs are priced individually. Floors are `10 minutes` for oracle runs and `30 minutes` for job runs. These are not fast liquidation or MEV execution rails. [Live capabilities](https://api.imd.fun/requests/capabilities).

**Inference — auditable break-even, in ETH rather than guessed dollars:** let `p` be ETH paid per IMD at procurement; `W` worker compensation; `R` independent verification compensation; `G` measured gas × effective gas price for job execution, oracle submission if any and withdrawals; `C` other incremental compute/storage not already in W/R; and `F/N` amortized fixed setup cost per accepted job. Then:

`c_job = 0.5p + W + R + G + C + F/N`.

If every job also buys an oracle, `c_job_oracle = c_job + 0.5p + incremental oracle gas`. Do not add the workers' own model expenses again when their quote already includes them. An all-IMD rerun procured as another paid job adds another `0.5p`; an externally hired reviewer belongs in R. Expected revenue for a job must cover failures too: if acceptance probability is `a`, cost per accepted outcome is `cost_per_attempt / a`, plus any acceptance-only payments.

**Inference — fee-funded ceiling:** if the operator assigned the entire recorded compute slice, its gross inflow would be `0.001 × V` ETH for gross canonical-pool ETH volume V. Before gas/other compute spending, at most `J × c <= 0.001V`, hence `V_break_even >= 1000 × J × c`. If only fraction `s` of the slice is authorized, `V_break_even >= Jc / (0.001s)`. This derivation assumes the recorded plan persists and money is actually collected; it excludes the wallet, NFT and paused reserve shares. A one-time claim balance is runway, not recurring revenue.

**Inference — customer and operator tests differ:** customer recovered value U should exceed its full job spend and incremental risk; worker W must cover its own compute and opportunity cost; reviewer R must cover a fresh rerun. No measured p, gas distribution, recurrent missed-payout value, W or R was established, so a numerical profit forecast would be invented. A conventional keeper's gas-plus-margin is the relevant price ceiling for deterministic claims. Keep the aggregate fee unchanged during the experiment; that avoids an incremental swap tax but does not prove the existing fee is harmless to volume.

## 11. Moonshot

**Inference — boldest version under the same rules:** a sponsor-funded maintenance market where CLAUS NFT seats and IMD seats compete to synthesize bounded repairs for new fee-program interfaces, publish full pool-state evidence and execute recovery actions against immutable postconditions. A new immutable v4 hook funds and owns the escrow ledger, not merely a dashboard; each job fixes code/state/spec hashes, worker/reviewer identities and maximum liabilities. Existing CLAUS stays transferable across venues, and job eligibility does not depend on token purchases. Sponsors can add jobs but cannot retroactively change their acceptance terms. The network has no general treasury-trading authority. ERC-8004 supplies discoverable identities and receipts, not a proof of honest operation; there is no assumed validation-registry address.

**Inference — smallest falsifiable experiment:** the same 10-day trial, with one real unseen interface case, a deterministic baseline, a worker and a separately controlled reviewer, a fresh fork rerun, and an atomic recovered-proceeds postcondition. The sponsor commits the budget before work. Pass only if the AI discovers a valid bounded sequence the baseline misses, the independent rerun succeeds, and measured recovered value exceeds full cost. That can justify a new proposal; it does not prove a network effect or satisfy a literal claim that all non-AI programs are incapable. A live experiment remains disallowed until the hook/admin/fair-opening gates pass. Day-one payer is the CLAUS operator from an explicitly approved budget; no agreement is inferred from its fee collector.

**Inference — why it may be a bad idea:** scarce missing interfaces may disappear after one adapter is written, leaving an ordinary keeper service beneath an expensive seat, bonding and review structure. The apparent customer could be recycling trading fees among related operators. A test suite can reward a clever but useless artifact, and two models can share the same mistake. CLAUS collateral falls with the ecosystem whose work it guarantees, while reviewers still need payment on failed attempts. A new hook/pool fragments liquidity and has no right to fees from other venues; the current frozen hook cannot become a general job-verification engine. Buying a proven external service or writing a small keeper may produce the entire benefit without a new network. POD's poster-refusal mechanism and Daydreams' settlement revisions are evidence that reproducibility and commercial acceptance remain different problems.
